# Effect polymorphism

A function that takes another function as an argument has a decision to make about the argument's effects. `apply_twice` doesn't perform anything itself — but whatever it's handed might:

```cronyx
fn apply_twice<T>(f: (T) -> T, x: T): T {
    return f(f(x));
}
```

That signature says the callback is pure, so `apply_twice` is pure. Hand it a function that logs and the compiler rejects the call: the argument performs `log` and the parameter type says it performs nothing. The combinator works for exactly one kind of callback, and you'd need a second copy of it for every effect you ever want to pass through.

## A variable that stands for a row

The set of effects in a type is called its **row**, and a row can be a type parameter like any other:

```cronyx
effect log {
    fn emit(msg: string): unit;
}

fn apply_twice<T, E>(f: (T) -> <E> T, x: T): <E> T {
    return f(f(x));
}

fn bump(x: int): int {
    return x + 1;
}

fn shout(x: int): <log> int {
    emit("saw " + str(x));
    return x + 1;
}

print(str(apply_twice(bump, 0)));

run {
    print(str(apply_twice(shout, 0)));
} handle log {
    fn emit(msg) { print("log: " + msg); }
}
```

```
2
log: saw 0
log: saw 1
2
```

`E` is an ordinary type parameter that happens to stand in a row. The signature now reads: *whatever `f` performs, `apply_twice` performs*. The first call settles `E` to the empty row and needs no handler; the second settles it to `log` and does. One definition, both callers.

Note where `<E>` sits — immediately before the return type, on both the parameter and the result. `(T) -> <E> T` is a function from `T` to `T` performing `E`; `: <E> T` is a return type of `T` performing `E`.

## Adding to a row

A row variable is a *tail*: it stands for whatever the caller brings, and you can name effects alongside it. `<log, E>` means `log` and whatever else:

```cronyx
effect log {
    fn emit(msg: string): unit;
}

effect ask {
    fn base(): int;
}

fn traced<T, E>(label: string, f: () -> <E> T): <log, E> T {
    emit("enter " + label);
    var result = f();
    emit("leave " + label);
    return result;
}

fn quiet(): int {
    return 7;
}

fn asks(): <ask> int {
    return base() + 1;
}

run {
    print(str(traced("quiet", quiet)));
    print(str(traced("asks", asks)));
} handle log {
    fn emit(msg) { print("log: " + msg); }
} handle ask {
    fn base() { return 41; }
}
```

```
log: enter quiet
log: leave quiet
7
log: enter asks
log: leave asks
42
```

`traced` performs `log` on its own account whether or not `f` does, so `log` is written down. Everything `f` brings rides along in `E` — nothing for the first call, `ask` for the second — and both handlers are installed by the caller.

## You usually don't write it

Rows are inferred, so a function you leave unannotated is row-polymorphic without your saying so:

```cronyx
effect log {
    fn emit(msg: string): unit;
}

fn twice(f, x) {
    return [f(x), f(x)];
}

fn bump(x: int): int {
    return x + 1;
}

fn shout(x: int): <log> int {
    emit("saw " + str(x));
    return x * 2;
}

var quiet = twice(bump, 3);
print(str(quiet[0]) + " " + str(quiet[1]));

run {
    var noisy = twice(shout, 5);
    print(str(noisy[0]) + " " + str(noisy[1]));
} handle log {
    fn emit(msg) { print("log: " + msg); }
}
```

```
4 4
log: saw 5
log: saw 5
10 10
```

`twice` was never told anything about effects and accepts both callbacks anyway. This is "known, not written" from [Why effects](./why-effects.mdx), applied to higher-order code: the annotation is what you write when you want the signature spelled out, not what makes the polymorphism happen.

You can see what was inferred with `typeof`:

```cronyx
effect logger { fn log(msg: string): unit; }
effect counter { fn tick(): unit; }

fn greet(name: string) { log("hi " + name); tick(); }
fn indirect() { greet("x"); }
fn pure_fn(n: int): int { return n + 1; }

print(typeof(log).name);
print(typeof(greet).name);
print(typeof(indirect).name);
print(typeof(pure_fn).name);
```

```
(string) -> <logger> unit
(string) -> <counter, logger> unit
() -> <counter, logger> unit
(int) -> int
```

`indirect` performs both effects because `greet` does, and `pure_fn` performs none — none of which is written in the source.

## Where you'll meet it

The standard library's list combinators are all row-polymorphic:

```cronyx
fn map<T, U, E>(items: List<T>, f: (T) -> <E> U): <E> List<U>
fn filter<T, E>(items: List<T>, f: (T) -> <E> bool): <E> List<T>
fn fold<T, A, E>(items: List<T>, start: A, f: (A, T) -> <E> A): <E> A
```

This is why you can `map` a function that logs, or `filter` with a predicate that asks a handler for a threshold. Without the row variable each of those would be pure-only, and the effectful case would need a parallel copy of every combinator.
